# Domain documentation

Single context: root CONTEXT.md is the glossary; docs/adr/ holds sequentially
numbered decisions. Read the glossary for spec, ticket, implementation, and
review vocabulary. Update it when a domain term is resolved, keeping it free
of code maps, plans, and implementation details.

Use domain-modeling for meaningful terminology/decision changes. Keep ADRs
short and reserve them for a real, consequential trade-off. Proposed decisions
stay proposed until reviewed. Runtime architecture belongs in the existing
docs/architecture.md; proposed changes belong in plan.md.

The package's goal tasks and this repository's development tickets are
different concepts. SDLC artifacts do not become runtime package features.
